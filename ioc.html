01 IoC-typen

Indicators of Compromise zijn observeerbare aanwijzingen dat een systeem is gecompromitteerd. Niet elke IoC is gelijk — sommige zijn triviaal voor een aanvaller om te wijzigen, andere raken de kern van zijn capability.

Pyramid of Pain — David Bianco (2013)

Hoe hoger in de piramide, hoe pijnlijker voor de aanvaller om eromheen te werken — en hoe waardevoller je detectie.

TTPs — Tactics, Techniques & Procedures · tough!
Tools — malware-families, exploit kits
Network & Host artifacts — file-paths, mutexen, registry keys, C2-protocol
Domain names
IP addresses
Hash values · trivial

Drie hoofdcategorieën

Atomic IoCs

Eén losse indicator: hash, IP, domein, e-mailadres. Makkelijk te delen, makkelijk voor aanvaller om te wisselen.

Computed IoCs

Afgeleid uit observaties: regex op log-strings, YARA-rules, Sigma-detecties, JA3/JA4-fingerprints. Vangen variaties op atomic-niveau.

Behavioral IoCs

Patroonbeschrijvingen van aanvallergedrag: "proces start cmd → spawnt PowerShell → leest LSASS". Bestrijken TTP-niveau.

Indicator-quality criteria

Niet elke IoC is bruikbaar. Toets per indicator:

  • Specificiteit — hoe waarschijnlijk dat een match écht kwaadaardig is? (CDN-IPs of cloud-fronting hebben veel false positives.)
  • Vluchtigheid — hoe snel veroudert de IoC? (Hashes per sample uniek, IPs/domeinen door de aanvaller wisselbaar.)
  • Context — TTP / actor / campagne / TLP-PAP / first/last-seen.
  • Bron — Admiralty-score, deelbaarheid (TLP) en aansprakelijkheid (PAP).
  • Verifieerbaar — kan een tweede bron de waarneming bevestigen?

Indicator-lifecycle

  1. Collection — uit feeds, sandbox, IR, OSINT.
  2. Validation — false-positive-check, dedupe, enrichment.
  3. Activation — uitrol naar EDR/SIEM/firewall, eventueel als detection of als block.
  4. Monitoring — true-positive ratio, hit-rate, drift.
  5. Retirement — verwijderen of degraderen wanneer waarde wegvalt.
